# =============================================================================
# backend/constraints.txt - the locked TRANSITIVE closure of requirements.txt
# =============================================================================
#
# WHAT THIS IS
# Every line in requirements.txt is an exact `==` pin, but those nineteen
# direct pins pull in roughly fifty more packages, and those are free to float:
# two installs a week apart can otherwise resolve different versions of grpcio,
# protobuf, cryptography or starlette from an identical manifest. This file
# closes that gap, so "resolved and installed together" becomes true of the
# whole graph and not just of the direct pins.
#
# Added under code review finding M5, which asked for the resolved closure to
# be committed as a lock artifact alongside a verified bcrypt pin. Both halves
# land together here, because they are coupled: a lock of the full closure
# necessarily pins bcrypt, so the lock could not be committed until the bcrypt
# version was authorised. See RESOLVED FINDING 3 and RESOLVED FINDING 4 in
# requirements.txt for the measurements behind that pin.
#
# HOW TO USE IT
#     pip install -r requirements.txt -c constraints.txt
#
# requirements.txt alone remains installable on its own, and that is what CI
# runs today (.github/workflows/backend_ci.yml:L24) - this file is ADDITIVE and
# needs no workflow change. A constraints file only bounds versions; it never
# causes a package to be installed. Nothing here contradicts a direct pin.
#
# HOW IT WAS GENERATED
# From a CLEAN resolve of requirements.txt into an empty CPython 3.9.25
# virtual environment, then frozen. Deliberately not frozen from a working
# development environment: that would have captured redis, async-timeout and
# pyjwt, which arrive from local `celery[redis]` and tooling installs and are
# NOT in this manifest's closure. Locking them would have misrepresented the
# manifest.
#
# VERIFIED
# The closure below resolves with a clean exit on CPython 3.9.25 and was
# exercised functionally, not merely installed: a form-encoded POST through
# OAuth2PasswordRequestForm returns 200 (python-multipart 0.0.20 against
# starlette 0.27.0), an HS256 encode/decode round trip returns its claims and
# a tampered signature raises JWTError (python-jose 3.5.0), and
# CryptContext(schemes=['bcrypt']) hashes and verifies with no "(trapped)"
# traceback (passlib 1.7.4 + bcrypt 4.0.1).
#
# MAINTENANCE
# Regenerate whenever a direct pin in requirements.txt changes, by the same
# clean-resolve-then-freeze route. Do not hand-edit a single line: a lock that
# has been partially hand-adjusted no longer describes any environment that
# was actually tested.
#
# KNOWN PROPERTY, recorded rather than suppressed: CPython 3.9 is past end of
# life, and google-api-core and google-auth emit unsupported-runtime warnings
# on it. The runtime is pinned at 3.9 by backend_ci.yml:L16-L19 and is fixed as
# no-change, so this lock honours the documented runtime. That constraint is
# also why python-multipart is capped at 0.0.20 - see requirements.txt.
# =============================================================================
